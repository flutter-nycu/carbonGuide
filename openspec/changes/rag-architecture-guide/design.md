## Context

- 基準：網站 `main` `a831af7`（RAG 工作台 11 頁已上線）、後端 `main` `34398dd`。技術事實以後端 `docs/rag.md`（2026-11-19）為準。
- 工作台放在 Shadow DOM，正式站 CSP 是 `style-src 'self'`，不能用 inline style。
- 外框 `Workspace.tsx` 在 `api` 為 null（後端未啟用）時，每一頁只顯示「RAG 後端尚未啟用」；頁面元件的 props 型別要求 `api` 不為 null。

## Goals / Non-Goals

**Goals：** 一頁讀懂整套 RAG 的流程與把關方式；每一步都能跳到相關的操作頁；顯示目前正式環境的實際設定；三種角色都能看；手機可用、鍵盤可操作。

**Non-Goals：** 跨頁反白的互動導覽、新 API、資料庫異動、新套件、改其他頁。

## Decisions

### G1 頁面位置
新增 `PageId` `'guide'`，編號 12，群組「認識系統」，放在最後。前 11 頁的編號與順序不變，避免既有文件與習慣失效。沒有 `readers` 限制。

### G2 外框特別處理
`Workspace.tsx` 在判斷 `api` 與角色之前先處理 `'guide'`，把 `api`（可能為 null）與 `role` 傳給 `ArchitecturePage`。導覽頁的 props 型別是 `{ api: RagApi | null; role: Role }`，不改其他頁的 `PageProps`。

### G3 內容與元件分開
文字、步驟、節點、小卡與辭典放在 `rag/guideContent.ts`，用型別描述；元件只負責呈現與互動。改文字不用動元件，也方便測試核對每一步都有說明、技術與節點。

### G4 架構圖用 HTML 而非單張 SVG
架構圖用有序清單（`ol`）排出五個區塊，箭頭用 CSS 畫。理由：中文字在窄螢幕要能換行、跟著字級放大，SVG 的 viewBox 做不到；清單本身就有讀屏可讀的順序。區塊是按鈕，目前步驟所在的區塊加 `aria-current="true"` 與標亮樣式（`"step"` 留給步驟圓點，避免讀屏念出兩個「目前步驟」）。桌機橫排；1000px 以下直排（900 寬時橫排每格只剩約 68px，「管理工作台」會斷字）。

### G5 分步說明的互動
- 兩條路線用 tablist 切換，左右鍵與 Home／End 移動焦點並直接切換（自動啟用，內容是本機資料，切換沒有延遲）。
- 步驟用圓點清單加「上一步／下一步」；步驟內容區用 `aria-live="polite"` 加 `aria-atomic="true"`，切換時讀屏念出整個新步驟。走到第一步或最後一步時，被按的按鈕會停用，焦點移到另一顆還能用的按鈕。
- 點架構圖的區塊：在目前路線找第一個用到該區塊的步驟；目前路線沒有用到時，切到有用到的那條路線。
- 「到這一頁看看」呼叫既有的 `useNavigate`，不改網址；要看的頁目前角色看不到時，按鈕照常切頁，由該頁顯示權限說明。

### G6 實際設定只讀、不花錢
用既有讀取方法：`listDocuments`（完成、處理中、需要留意的數量）、`getSettings`（先找幾筆、參考幾段）、`listVersions`（目前使用的版本，只給 owner、editor）、`getBudget`（只給 owner）。模型名稱沒有 API，寫在內容檔並註明核對日期。後端未啟用時一個請求都不送。不輪詢；頁面從隱藏切回顯示時重讀一次，在 05 發布新版本後回來就看得到。頁上的題數、金額、天數與上限取自 `LIMITS`，和工作台其他檢查用同一份常數。

### G7 樣式
新增的 class 都加 `guide-` 前綴，附加在 `styles.css` 末尾，沿用既有色票與 `.panel`、`.tag` 等樣式。

## Risks / Trade-offs

- 內容和實際系統脫節 → 內容檔標註依據的文件與日期；後端架構變更時同步更新，並列入後端 `docs/rag.md` 的維護提醒。
- 第 12 頁打破「不放導引」的原則 → 規格明確寫成唯一例外，跨頁測試對其他 11 頁照舊檢查。
- 只給部分角色的資料 → 依 G6 只對有權限的角色呼叫，避免無權限查詢與誤導的空資料。
