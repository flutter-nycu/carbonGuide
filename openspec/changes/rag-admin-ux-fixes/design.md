## Context

RAG 工作台是 `src/push-admin/rag/` 的原生 JavaScript 假資料原型，由 `RagWorkspace.tsx` 掛進 Shadow DOM。每次操作後 `render()` 會重寫整個 `main`。整合時把樣式裡的 `body` 換成 `.rag-body`，連帶改壞 `.help-body` 與 `#dialog-body`。原型不得使用 `localStorage`／`sessionStorage`（既有測試檢查），所有狀態只在記憶體。

## Goals / Non-Goals

**Goals:** 修正 P0 錯誤；縮短到達主要內容的距離；讓草稿與發布狀態隨時可見；設定頁符合已確認的決策；手機版文件列表不用橫向捲動；鍵盤焦點不遺失。

**Non-Goals:** P2 的字級、對比、重複提示與推播工作台外觀統一；任何真實後端串接；改變推播工作台程式。

## Decisions

- **草稿狀態判斷**：每個發布版本保存發布當下的草稿修訂號。草稿修訂號等於目前使用版本的修訂號，就代表沒有未發布修改。發布與回滾只切換目前使用的版本、重設審核，不再遞增草稿修訂號；否則剛發布完就會顯示「有未發布的修改」。沒有修改時停用審核與發布，避免產生內容相同的新版本。回滾後若草稿比回滾目標新，草稿沿用原本的評測結果，只需重新審核。
- **側欄狀態卡**：取代原本寫死 v0.1 的 `.workspace` 區塊，每次 `render()` 一起更新；手機版改為精簡的一列，不隱藏。
- **焦點還原**：`render()` 前記錄目前焦點元件的識別（`data-action`＋`data-id`，或 `id`），重繪後找回同一元件；找不到就以 `preventScroll` 聚焦 `main`。開啟彈窗時記錄開啟者，彈窗 `close` 事件後還原。試問後聚焦回答區（`tabindex="-1"`）。不另加 `aria-live`，因為重繪會重建節點，新插入的 live region 不保證會被朗讀；改由焦點移動讓螢幕閱讀器讀出回答。
- **引導收合**：「第一次使用」在記憶體記錄是否已離開過知識庫頁；管理員手動切換後以管理員的選擇為準。各頁操作說明只有管理員展開後才保持展開。
- **設定資料**：`settings` 改為回答與檢索設定；索引設定獨立成唯讀的 `indexProfile`，依網站 repo 的 `rag-v1-implementation-plan.md` 顯示 OpenAI 候選值。發布時兩者一起進快照。試問「查無資料」時使用所選範圍的回覆文字，草稿用目前設定，已發布用發布快照，讓設定在示範中有可觀察的效果；其他設定只記錄版本。
- **匯入逐列設定**：預檢項目自帶 `purpose`／`domain`；改動任一列時更新「上一次選擇」，之後新增的列帶入此值。
- **手機卡片**：只對文件列表加 `doc-table` class 與 `data-label`，720px 以下用 CSS 把列轉成卡片；其他表格維持可橫向捲動。
- **原型連結**：建置結果沒有 `prototype.html`，而且 `rag-admin-workspace` 要求不得有獨立公開的 RAG HTML 入口，所以只移除連結、保留 repo 路徑說明，不把檔案加入建置。

## Risks / Trade-offs

- 回滾不再強制重新評測：草稿內容沒變時沿用評測結果。若之後要求回滾一律重評，只需在回滾時清除評測修訂號。
- 焦點還原依賴 `data-action`／`data-id` 的唯一性；同頁出現兩個相同識別的按鈕時，會回到第一個。
- 卡片版面以 CSS 轉換表格語意，螢幕閱讀器仍讀為表格列；`data-label` 只提供視覺標籤。
