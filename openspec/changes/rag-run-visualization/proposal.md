# RAG 每次詢問／測試的流程與成本視覺化

## Why
使用者要求讓管理介面能看見每次詢問或測試實際經過哪些步驟、在哪裡失敗，以及花費多少。目前只有零散的評測 JSON 與用量紀錄，無法從介面完整追蹤。

## What Changes
- 在試問、評測結果與互動紀錄共用「執行詳情」，依 request/trace ID 顯示實際路徑、節點時間、狀態、模型與知識版本。
- 區分觀察到的 token 用量、依價格版本計算的費用估算、執行前保守預留及供應商對帳金額；未知顯示未取得，不記為零。
- 節點包括權限／額度、QA命中、問題embedding、向量與關鍵字檢索、RRF、來源門檻、可選問題改寫／工具、模型生成、引文與規則驗證、回答／拒答。未執行的分支標為略過，重用資料標為重用，人工重試另有attempt。
- 先實作本機回答追蹤與失敗診斷，再建置服務端trace儲存/API，最後接上React介面與真實查詢。目前已完成歷史評測的儲存與 React 檢視子階段，完整即時流程及部署仍未完成；進度見 tasks.md。

## Impact
網站React試問／評測／互動紀錄、App後端trace契約與權限、費用帳本及資料保存。維持既有管理員限制，供應商key只在伺服器。完整產品規劃以網站rag-v1-implementation-plan.md的5.2節為準。
