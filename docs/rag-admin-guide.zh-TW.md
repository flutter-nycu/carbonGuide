## RAG 後台使用指南 · 從第一次登入開始

繁體中文版 | 初次使用、內容整理與人工審閱

> 適用：受保護的管理員 Preview，2026-10-28 版。真實內容仍待人工審查；一般回答服務關閉，Flutter App 尚未接入。

這本指南回答三件事：這頁先做什麼、按鈕按下去會改什麼、結果不如預期時去哪裡查。你可以先只做閱讀與核對，熟悉之後再修改候選資料。

| 想做什麼 | 先看哪個章節 |
| --- | --- |
| 找文件、看原文 | 文件與段落／上傳與處理狀態 |
| 看懂移除引用、排除段落 | 段落修訂／QA 引用 |
| 試問、知道最後回覆什麼 | 版本試問／互動紀錄與拒答 |
| 比較品質與成本 | 流程與費用／固定題庫評測 |
| 改設定、準備新版本 | RAG 設定／計算資料／知識版本 |

每一頁上方新增「這頁怎麼用？」可展開短說明。完整技術原理、名詞與未來雲端解析方案，請搭配《RAG 技術文件》。

## 快速上手：先看，再改，再測



開啟 Preview 的 /push-admin#rag。若先出現 Vercel 登入，完成後還需要用 CarbonGuide 既有管理員 Google 帳號登入。這是兩層不同的權限；不是任意 Google 帳號都能使用。

| 順序 | 操作與觀察 |
| --- | --- |
| 1 文件與段落 | 搜尋文件 → 檢視 → 選版本與集合 → 核對原文、物理頁碼、品質警示。 |
| 2 通用 QA／人格與提示詞 | 先讀現有草稿；需要修改時才編輯並儲存。QA 還要補有效引用。 |
| 3 知識版本 | 選既有快照看內容。新增版本要選 ready 集合、提示詞與必要草稿再固定。 |
| 4 試問 | 先選有限輪次及版本，再送出一題。確認結果與引用，不要連點重送。 |
| 5 互動紀錄 | 讀完整問題、實際回覆、引用與流程；切換人工試問／自動評測。 |
| 6 人工審閱 | 記錄問題與來源依據，準備新候選版本。正式核准與發布是獨立決策。 |

> 檢視、搜尋、分頁、讀歷史不呼叫模型。儲存草稿會寫資料但不直接呼叫模型。送出試問、執行評測及維護者啟動 embedding 才可能產生模型費用。

灰色按鈕通常表示角色不足、缺必填欄位、資料尚未 ready、額度不足或正在處理。先讀鄰近提示；不要用重新登入或重複提交來猜。

## 文件與段落：怎麼找到要看的內容



| 控制項 | 按下後會怎麼樣 |
| --- | --- |
| 搜尋文件 | 依名稱、用途或領域縮小目前列表。不是詢問 Gemini。 |
| 上一頁／下一頁文件 | 文件每頁 12 份；不會載入整個長列表再把詳情放在底部。 |
| 檢視 | 在當前視窗開啟詳情。桌面為對話視窗，手機為滿版；右上角關閉或 Esc 回到原列表位置。 |
| 文件版本／段落集合 | 選擇此次要看的解析或修訂結果。每頁 25 段，換頁回到新頁開頭。 |
| 編輯用途、領域與引用範圍 | 展開分類表單。按「儲存分類草稿」才寫入；舊快照不變。 |
| 修訂或排除此段 | 展開該段的候選修訂表單；只是展開不會改資料。 |

### 先看三項資料

處理狀態：是否完成解析與向量準備。內容狀態：是否仍在草稿／審核中。品質警示：是否有 OCR、缺字、隔離段落或頁面問題。三者不能互相取代。

> 物理頁碼指 PDF 檔案中的頁序，可能與書上印的頁碼不同。段落識別碼用來綁定引用；第幾段是排列順序，不是可跨版本沿用的永久 ID。

## 上傳、網址與處理進度



| 按鈕或狀態 | 效果與注意事項 |
| --- | --- |
| 選擇原始檔 | 先在本機挑檔，尚未上傳。支援 PDF、DOCX、TXT、JSON；單檔上限 20 MiB。 |
| 上傳並核對 | 保存私有原始檔並下載核對 hash。成功後建立後續工作，不會自動在雲端解析。 |
| 更新處理狀態 | 重新讀取工作狀態，不會啟動或重跑解析。 |
| 取得下載授權 | 產生短效下載入口；再按下載原檔才開啟。過期時重新取得，勿轉傳含授權的連結。 |
| 網址登記／抓取工作 | 只接受列管 HTTPS 來源。先登記，維護者的 worker 才抓取與保存快照；不是任意網頁搜尋。 |
| pending／parsing／embedding／ready | 依序為待處理、解析中、向量化中、準備完成；仍須內容審查。 |
| failed／uncertain | 失敗或結果不明。讀原因與原工作 ID，先核對再決定是否重做。 |

上傳完成後一直待處理，通常是本機批次尚未啟動，不是按「更新」就會開始。把文件與工作識別碼提供維護者即可，不要提供金鑰或整份私人原文。

> 20 MiB = 20,971,520 bytes。超過時先請維護者評估分卷及頁碼對應，勿直接提高限制。未來雲端背景解析的設計寫在技術文件，目前沒有部署。

## 「從新集合排除此段」是什麼



假設文件有 80 段，第 12 段是錯誤 OCR。勾選「從新集合排除此段」表示：要建立一份新候選集合，裡面不收錄這段；原始 PDF、舊 80 段集合和舊回答仍保留。不是從全系統抹除這段。

| 步驟 | 實際效果 |
| --- | --- |
| 1 展開修訂 | 看原文與頁碼，確認真的需要修改或排除。 |
| 2 勾選排除 | 只改這個表單，修訂文字欄停用。還沒有存入資料庫。 |
| 3 填修訂依據與原因 | 寫清楚頁碼、辨識問題和處理理由；不要只寫「不好」。 |
| 4 建立待審修訂版 | 後端建立新集合並記錄原因。不允許把所有段落排除到空集合。 |
| 5 檢查新集合 | 保留段落會有新 ID。QA 與計算引用須改綁新集合，不能只沿用舊 ID。 |
| 6 固定新快照並測試 | 選入新集合後才影響新輪次；不會默默改掉舊快照的問答。 |

> 若修改文字而非排除，改動的 embedding 輸入要由維護者重新向量化。短修訂限制為文件標題＋章節＋正文合計 1,800 UTF-8 bytes；長表格請重新解析，不能任意截斷。

反悔方式：尚未儲存就關閉表單；已建立新集合則保留紀錄，選擇正確的舊集合或再建立修正版本。不要以刪除歷史來掩蓋修改。

## 通用 QA：先存答案，再綁來源



通用 QA 是管理員預先寫好的標準問答。現行 v1 只在問題正規化後完全命中時使用；不是看到大致相似就套用。未命中才進行文件檢索。

| 控制項 | 效果 |
| --- | --- |
| 新增草稿／編輯 | 開啟目前視窗中的編輯表單；填問題、標準回答與來源說明。 |
| 啟用 | 讓這則 QA 可被新快照選入，不等於已發布或立即對所有輪次生效。 |
| 儲存草稿 | 保存文字；舊快照中的 QA 複本不改變。 |
| 核對 QA 引用 | 展開後讀取這則 QA 的正式來源清單。來源說明欄只是備註，不能代替引用。 |
| 關閉詳情／Esc | 離開編輯視窗，未存修改捨棄。儲存期間暫時不能關閉。 |

### 一個可送入版本的 QA

問題清楚、答案有適用條件、至少一筆有效來源引用。先保存 QA，再到列表展開引用，填入文件段落 ID 及原文摘錄；最後建立知識版本時選入這則 QA 與同一來源集合。

> 只修改 QA 草稿，舊輪次回答不變是正常的：輪次固定使用原快照。需要比較修改前後，應建立新快照與新輪次。

## 「移除引用 1」到底移除什麼



引用 1 是這則 QA 來源清單中的第一筆。按「移除引用 1」只從目前編輯清單拿掉這筆來源；QA 答案、文件、段落與舊快照都不會被刪掉。按下儲存後，才用新的清單取代這則 QA 草稿的來源清單。

| 按鈕／欄位 | 效果與檢查 |
| --- | --- |
| 新增引用 | 新增一個空欄位，最多 5 筆。先填完，還沒有儲存。 |
| 段落識別碼 | 從文件詳情複製要引用的段落 ID；同一 QA 不可重複相同段落。 |
| 逐字摘錄 | 直接摘原文 5–800 字，保留數字、單位與上下文。不要自行改寫成「差不多的意思」。 |
| 移除引用 1 | 清單顯示「尚未儲存」。移除後其他引用可能重新編號。 |
| 儲存並核對引用 | 整批核對並保存；任何一筆不合法則整批不變。資料被他人更新時會要求重新讀取。 |
| 清空所有引用後儲存 | 允許保存無引用草稿，但這則 QA 暫時不能選入快照，至少補一筆有效引用。 |

> 想撤銷未存的移除：收合「核對 QA 引用」後重開，會重新讀取已保存清單。已儲存才發現錯誤：重新加入正確 ID 與摘錄，再儲存。

若文件剛做段落修訂，新集合所有段落會取得新 ID。要以新集合建立快照時，相關 QA 與計算資料的引用必須重新綁定。

## 人格與提示詞：控制回答語氣



| 內容 | 用途與操作 |
| --- | --- |
| 人格名稱／指令／語氣示例 | 例如希望親切或精簡。填完儲存草稿；啟用後可被快照選入。 |
| System Prompt | 寫回答方式與風格偏好；保存提示詞後，建立快照時選擇該筆。 |
| 新增／編輯／儲存 | 開啟對話視窗、修改草稿、寫入資料；不呼叫 Gemini。 |
| 選入知識版本 | 只有快照選入的人格與提示詞才影響該版本；試問再選此版本可用的人格。 |

建議例子：「以一般民眾容易理解的繁體中文回答，保留適用日期與限制，不把相關性說成因果。」避免要求模型隱藏不確定性或略過來源。

> 人格與提示詞不能越過後端權限、費用、來源與數字檢查，也不能保證錯誤設定仍產生正確回答。修改草稿不會回寫舊快照，測試時請確認選的是新版本。

## 版本試問：一題一題確認



| 操作 | 按下後會怎麼樣 |
| --- | --- |
| 建立有限試問輪次 | 選固定快照，填預算、題數、UTC 個人每日上限。建立限制，尚不呼叫模型；新輪次不增加共用預算或重置每日使用量。 |
| 選輪次／人格 | 指定要測的內容版本與語氣。輪次到期、停止或額度用完就不能新增題目。 |
| 送出或查詢相同試問 | 首次送出占用題數，可能進 embedding／回答付費呼叫。同頁未重新整理且輸入相同時沿用識別碼。 |
| 另建同題測試 | 清除本頁同題識別碼，下次送出是另一筆新測試，另占題數與可能費用。 |
| 停止此輪次 | 阻擋後續步驟；已送出的外部模型呼叫無法追回，不退款。 |
| 封存超過 5 分鐘的中斷請求 | 把符合條件的中斷請求標記結果不明，不重跑、不退款。 |

> 連線中斷時先到「互動紀錄」查原題。即使新題額度已滿，讀歷史仍可進行。不要重新整理後再貼同題送出，因為前端記憶體中的識別碼可能已遺失。

如果只想了解畫面，先讀現有歷史題即可，不必建立新輪次。一般單題不是帶記憶的聊天室；前一題內容不會自動帶到下一題。

## 系統無法回答時，實際回覆什麼



> 現行 v1 的固定拒答：
> 「目前這個知識版本沒有足夠且可核對的資料回答，請補充問題或交由管理員確認。」

| 畫面狀態 | 你能確定的事 |
| --- | --- |
| 已回答 | 顯示已保存的模型／QA 答案，或確定性計算結果。仍需人工核對。 |
| 資料不足或驗證未通過 | 屬於拒答；詳情的「本次實際回覆（拒答）」顯示當時保存的正文。缺證據、引用不合格或完整帳單不支援都可能造成拒答。 |
| 未完成（failed） | 沒有可確認的最終答案。系統錯誤不是一則已保存的正常拒答，不能憑空補出當時回覆。 |
| 結果待確認（uncertain） | 外呼或記帳結果不明，無法確認最終回覆；預留保留。查原請求，勿當成免費重試。 |
| 已受理／處理中 | 還沒有最終回覆。稍後重新讀取既有紀錄。 |
| 超過保留期限 | 正文與詳細流程 30 天後不可讀；狀態與費用仍保留，無法由現在設定還原舊答案。 |

「給管理員的處理說明」用來解釋原因，例如數字或單位沒有逐字支持。這段說明與保存的最終回覆分開，不會被冒充成使用者當時收到的答案。

> 目前只有後台測試，Flutter 尚未接入。上述描述後端保存／回傳的結果，不能宣稱 App 使用者已看過。未來 App 對系統失敗、逾時的提示與重試介面需在接入時另定。

## 互動紀錄：找問題、答案與證據



| 操作 | 結果 |
| --- | --- |
| 紀錄來源：人工試問 | 預設篩選人手送出的題目。要看自動題庫，切換為自動評測或全部新版紀錄。 |
| 卡片摘要 | 直接讀問題與回覆摘要；拒答卡片標示「實際回覆 · 拒答」。 |
| 查看完整問答與流程 | 在當前視窗讀完整問題、實際回覆、原因、引用與費用。只讀，不重新問模型。 |
| 展開引用 | 核對來源文件、頁碼、原文摘錄及段落 ID。不是編輯 QA 的「移除引用」功能。 |
| 重新整理問答／分頁 | 每頁 20 筆，重新讀取原紀錄，不增加題數或模型成本。 |
| 舊版追蹤 | 舊 pilot 沒有保存問答正文，只有代碼與流程，不能事後還原。 |

只有 owner 可以讀完整互動紀錄。找不到內容時先確認篩選器、頁數與 30 天留存期限；若讀取失敗，畫面提供重讀，避免把權限錯誤當成空列表。

> 歷史回答是當時的結果。來源後來停用或新版本修正，不會把舊回答變成新版本答案；做審閱時一起記錄 request ID 與快照版本。

## 流程與成本：每個節點怎麼看



| 節點 | 正在做什麼 |
| --- | --- |
| 版本與權限／服務範圍 | 檢查身份、輪次、快照與是否屬於支援範圍。 |
| 通用 QA | 找正規化後完全命中的標準問答；略過不一定是錯誤。 |
| 問句向量化／混合檢索 | 把問題轉成向量，再合併語意與關鍵字搜尋排名。 |
| 問句改寫／再次檢索 | 只有允許且證據不足時最多一次，可能增加模型成本。 |
| 引用內容選擇／模型回答 | 套用門檻與大小限制，將可用文字交給模型。 |
| 引用與數值驗證 | 核對引用編號、原文、數字及單位，不通過就拒答。 |
| 確定性計算 | 依指定版本資料計算，不讓模型心算。 |

點節點可看狀態與耗時；「展開此步驟的技術資料」才顯示 JSON。略過代表本題不需要該步驟；失敗需讀原因。步驟耗時不等於單一模型費用。

> 模型預留：先占的安全額度，不是扣款。用量估算：供應商回傳 token 後依固定單價算。帳單金額：已匯入且核對的實際費用。未知不等於 0，文件前置 embedding 不應重複加到每題。

## 固定題庫評測：批量測試會做什麼



| 按鈕 | 效果與成本 |
| --- | --- |
| 匯入固定題庫 JSON | 先選檔並檢查格式，最多 64 KiB；尚未保存。題庫由維護者準備，去除個資。 |
| 保存這份固定題庫 | 保存不可變題庫；相同內容不重複建立，開發題與驗收題不可重疊。 |
| 建立評測批次 | 選題庫與輪次，一次保留整份題庫的輪次及今日題數；尚不呼叫模型。 |
| 執行下一題或產生報告 | 執行下一個待處理題，可能付費；全部完成才產生報告。 |
| 續跑剩餘題目 | 依序跑剩餘題目，可能連續呼叫付費模型；不自動重跑已失敗或未知外呼。 |
| 本題後停止 | 目前題繼續，前端不再要求下一題；不撤回已開始呼叫。 |
| 重新讀取評測 | 讀取批次與報告，不自動續跑。 |

切換離開試問頁會停止前端續跑迴圈，已送出的題目仍可能完成。恢復時選原批次讀狀態，不要另外建立批次掩蓋失敗。

> 歷史驗收為 36/40，仍未達發布門檻。Recall@5 是來源覆蓋，引用有效率是機械檢查，不是整體答案正確率；原始失敗與費用必須保留。

## 知識版本：固定、審核、發布



| 控制項 | 效果與前提 |
| --- | --- |
| 建立送審版本 | 填名稱，選每份文件一個 ready 集合、提示詞及需要的 QA／人格／計算資料。 |
| 固定快照，準備評測 | 複製並固定這版內容與設定；之後改草稿不回寫此快照。QA 至少一有效引用且屬於選入集合。 |
| 內容與審核 | 選版本看來源、品質警示、hash 和評測；完整 JSON 預設收合。 |
| 記錄人工核准／退回修改 | 勾選已核對並填原因，新增對此 hash 的決策，不會自動改內容或發布。 |
| 發布此版本 | 須有效人工核准及同版驗收全部門檻。切換使用中知識版本；一般回答服務仍關閉。 |
| 回滾至此版本 | 僅可回到曾發布且仍符合條件的版本；保留切換紀錄。 |
| 停用目前版本 | 清除使用中版本；不刪內容、不自動停止所有候選試問。 |

> 發布門檻：同一版本至少 40 題驗收且全部通過，Recall@5 至少 0.9、引用有效率 至少 0.95、數值失敗與越權來源均為 0，再加有效人工核准。前端按鈕與後端都檢查；空報告不是通過。

本次使用目的仍是人工審閱，沒有代替你核准真實內容。需要修改時建立新候選與新快照，保留原版與失敗報告。

## RAG 設定：哪些值真的影響 v1



| 欄位 | 現行行為 |
| --- | --- |
| 回答風格 | 作為快照中的語氣偏好，仍受來源與驗證規則限制。 |
| 檢索候選數／引用段落數 | 預設 20／6。新快照最大 50／12；證據不足時可能比設定少。 |
| 向量相似度門檻 | 預設 0.72。提高可能更常拒答，降低可能引入不相關來源；不是正確率。 |
| QA 命中門檻 | 保留草稿欄位；現行 v1 使用正規化後完全命中，不用這個數值做模糊 QA 比對。 |
| 資料不足時的回覆 | 保留草稿欄位；目前 v1 固定拒答來自後端回答契約，修改此欄不改 v1 實際拒答。 |
| 每人每日題數 | 一般服務草稿欄位；有限試問以輪次的個人 UTC 日上限與共用預算為準。 |
| 儲存設定草稿 | 寫入草稿。需要新快照及對應輪次才會使用可生效的設定，舊版本不變。 |
| 改寫／工具／索引設定 | 頁面顯示狀態；新快照另選是否允許改寫及工具。更換向量 profile 要由維護者建立新資料與重新評測。 |

> 目前仍可看到為後續一般服務保留的欄位，不能把「能填」等同「v1 已使用」。以此表、快照內容和實際試問流程為準。

## 計算資料：不是讓模型自由算數



| 操作 | 效果 |
| --- | --- |
| 新增計算資料 | 選活動量 × 排放係數或非時間電價級距，建立有來源的草稿。 |
| 地區／期間／單位／限制 | 說明哪個地區、哪段期間、何種活動可用；缺少時不應套用。 |
| 係數或級距 | 活動量用指定單位乘係數；電價用完整一或二曆月級距計算，不代表整張帳單。 |
| 來源引用 | 指向文件段落與摘錄，或原始係數 ID＋hash。引用一樣要和選入版本一致。 |
| 瀏覽原始係數／以此建立草稿 | 將匯入原始列帶入編輯，不等於核准。先核對單位、年份、用途及問題標記。 |
| 儲存計算草稿 | 保存待選內容，不呼叫回答模型；還要選入快照並允許工具。 |
| 試問中選計算資料 | 填活動量、日期或用電量等固定欄位，由程式計算；仍有輪次和題數限制。 |

程式採八位小數的固定精度運算，避免浮點誤差；這只處理算術，不能自動判斷係數是否最新或適用。

> 既有電價示例是 2025 年特定期間的候選資料，不可直接當作現在的完整應繳帳單。一般問句中的「幫我算」也不會讓系統自由挑任意公式。

## 預算、帳單與停止操作



| 操作／欄位 | 怎麼理解 |
| --- | --- |
| 預算活動 | 文件準備、試問與自動評測共用上限；建立新輪次不會增加總預算。 |
| 安全預留／上限 | 先保留的可用額度，不等於實際帳單；未知結果保留額度。 |
| 已知用量估算／未知次數 | 只把完整 usage 算成估計費用；未知次數不能算免費。 |
| 停止這個共用預算的後續呼叫 | 停止本活動後續模型呼叫，影響相關工作與輪次；已發出外呼不能追回，也不退款。 |
| 重新整理費用與狀態 | 讀取既有帳本，不啟動模型或釋放預留。 |
| 帳單 CSV | 先篩選本活動的模型費用，轉成 USD，以 UTC 期間匯入；不要把預付儲值填成花費。 |
| 確認這筆活動費用 | 將該列帳單正式記錄，不能覆寫。先核對參考編號、起迄時間與金額，避免重複／重疊期間。 |

CSV 欄位：reference, period_start, period_end, amount_usd。檔案最多 64 KiB／20 列。選檔只是讀入，逐列確認才寫入；期間結束時間不包含在內。

> 本輪模型活動曾獲 US$5 上限；即時餘額以畫面與帳本為準。本指南不重新查費用，也不新增模型呼叫。未來雲端解析費用另列，不受這個模型活動上限自動涵蓋。

## 遇到問題，先做哪一步



| 看到的情況 | 下一步 |
| --- | --- |
| 按檢視不知道跑到哪 | 目前在對話視窗；看頂部標題，右上角關閉／Esc 回列表。手機只捲詳情區。 |
| 已上傳但沒有段落 | 看處理工作是否 pending；請維護者啟動本機解析／向量批次。刷新不等於開始。 |
| 移除引用後反悔 | 未存：收合重開取回原清單。已存：重新加入正確段落與摘錄。 |
| 建快照說引用不符 | 檢查是否換了段落集合；修訂後段落 ID 都更新，QA／計算引用需重綁。 |
| 改了草稿但答案沒變 | 輪次仍綁舊快照。建立新快照、選對新輪次再測。 |
| 拒答但明明有資料 | 核對版本是否選入、檢索是否找到、門檻、引用或數字單位原因，不只看模型是否有生成。 |
| 連線中斷／費用未知 | 保留 request ID，先查原紀錄。不要另建同題或把未知當成零元。 |
| 保存失敗／資料已更新 | 先保留必要修改筆記，再重新讀取最新內容；不要盲目覆蓋。 |
| Google 403／429 | 交維護者核對專案、API 權限、計費或配額，提供原因碼與 request ID，不貼 key。 |

> 人工審閱建議記錄：問題、request ID、快照版本、來源頁碼、哪句不正確、希望如何修正。先核對證據再建立新候選；不要刪掉失敗紀錄或改舊測試分數。
